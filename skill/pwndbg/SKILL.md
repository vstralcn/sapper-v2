# pwndbg 远端调试

通过已配置的 `pwndbg` MCP 操作远端 GDB。围绕当前调试假设获取必要证据，按目标选择工具，不固定解题路线。

## 环境与连接

本工作区约定的连接方式是本机 MCP 客户端启动 SSH，由 SSH 在远端启动 stdio 服务：

```text
Agent → 本机 ssh → huawei-guiyang 上的 pwndbg-mcp → pwndbg / GDB → 目标程序
```

- 当前配置使用远端 `/root/.local/bin/pwndbg-mcp --transport stdio --pwndbg /usr/bin/pwndbg`。以本次实际加载的配置为准；skill 本身不会注册 MCP、建立连接或安装依赖。
- 工具中的可执行文件、libc、loader、输入文件与工作目录均按远端环境解释。不要把本机路径直接交给远端 GDB，也不要假设工作区已同步。
- 本机附件需要时，通过已有 Shell/文件传输能力上传到本任务的独立远端目录，核对文件摘要和执行权限；记录本机与远端路径对应关系。不要覆盖其他任务的同名文件。
- 先发现当前可用工具并阅读所需工具的参数说明；工具数量、名称和输入格式可能随版本变化，不凭记忆编造接口。按当前需求检索工具，不逐个调用全部工具探测能力。
- 若 MCP 未加载或连接失败，报告实际错误及缺少的配置。已有 Shell/SSH 能力可用于批量 GDB 或 core 分析，但应明确这是另一条执行路径；单独启动的 GDB 不会继承 MCP 内的状态。

## 会话与状态

- 首次操作或恢复后，确认所加载目标、架构、启动参数、工作目录，以及进程处于未启动、运行、停止还是退出状态；按需要确认 libc/loader、ASLR 设置和映射。
- 新的 MCP 服务进程按新的调试会话处理。恢复 Agent 对话或 Sapper 会话快照，不代表恢复了原 GDB 进程、断点或被调试进程。
- 同一个 GDB 会话中的改变状态操作应串行进行。运行或继续后，确认停止原因与当前状态，再进行依赖该状态的寄存器、内存或堆检查。
- 每次重启或重新连接后，重新确认断点与地址；PIE、libc、栈、堆基址可能变化。交接优先记录模块与偏移、符号和复现输入，不把旧进程的绝对地址当成新进程的地址。
- 每个 MCP 连接的独立 GDB 不等于远端文件和资源隔离；输入、输出、core、脚本等使用任务独立路径，不操作其他任务的进程。

## 工具选择与输入

- 优先使用与任务对应的专用工具；缺少覆盖时，再使用服务实际提供的通用 GDB 命令工具。遵循发现到的 schema，不猜测工具是否支持多条命令或异步调用。
- 检查内存、反汇编和堆时限定地址范围、长度或数量，先取能区分当前假设的输出，再按证据扩大范围。默认使用文本；只有文本不足以判断时才请求图像。
- GDB 命令输入与被调试程序 stdin 是不同通道。发送程序输入前，确认工具的接收对象、编码、换行、EOF 与二进制字节表达方式，避免把 payload 交给 GDB 命令解释器。
- payload 包含 NUL 或不可打印字节时，使用工具明确支持的字节输入；否则在远端写入二进制文件并采用已确认可用的输入重定向方式。文本中的 `\x00` 不等于实际 NUL 字节。
- 程序无输出或调用超时不等于崩溃。先区分等待输入、运行中、命中断点、收到信号和连接中断；超时后先查询状态，不盲目重发 run、continue 或 payload。

## 调试与验证

按需选择以下操作，不要求每次走完：

- 崩溃定位：结合停止信号、故障指令、寄存器、栈回溯和相关内存，确认可复现的输入及触发位置。
- 栈与控制流验证：使用符合目标位宽和端序的 pattern 或已知字节确认覆盖位置；区分寄存器可控、返回地址可控和已实现目标控制流。
- 堆分析：先确认实际 libc 与分配器版本，再解释 chunk、bin、tcache 和指针编码；一次内存快照不足以证明整个分配序列的因果关系。
- 利用验证：记录 GDB 对 ASLR、环境变量、工作目录及启动方式的影响。调试器内成功只支持该环境下的结论；若任务要求脱离调试器或远端服务成功，应在对应条件下复现。

## 失败恢复与交接

- 调用失败时保留错误和当前假设，先查目标及连接状态。相同条件下重复失败后，改变输入通道、检查会话或缩小命令范围；不要无信息地循环重试。
- 重建服务或 GDB 前，保存可复现命令、输入文件和关键证据；只清理本任务创建的进程、断点和文件，不使用全局 kill 或清理操作。
- 交接保留：目标及依赖的远端路径/摘要、运行条件、复现输入、关键断点或模块偏移、已验证观察、失败尝试和下一步。若工作区已启用 Sapper 图，按现有协议写入摘要与证据路径；不默认注入整段调试日志。
- 区分已观察事实与待验证推断。工具调用成功、程序停止或一次异常，均不能单独证明漏洞可利用或任务完成。
