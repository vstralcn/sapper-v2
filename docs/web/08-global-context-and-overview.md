# 全局上下文与总体概览

日期：2026-11-02 · 版本：v0.6 · 原 agent、工具和共享图继续使用原实现。

## 1. 首页

登录、刷新页面或点击侧栏“总体概览”后，显示全部工作区、活动角色、待办意图、事实数量、角色动态和最近运行。右侧显示共享环境的启用状态、版本、注入方式，以及执行机的系统／架构、Python、tmux 和 Claude CLI 可用性。

首页不再根据上次选择自动进入工作区。点击工作区名称或“打开工作区”后进入原文件／终端／角色界面；“查看输出”进入对应任务的运行记录。返回概览会关闭当前浏览器的终端订阅，不停止原会话。

执行机信息来自 Web 所在环境；容器内显示容器看到的环境，不能把它当作远端资源已连接的证明。活动角色来自登记会话，不把 watchdog 当作模型角色。多题指挥官按一个角色统计，在各自范围内的工作区显示关联。

## 2. 配置共享信息

点击侧栏“全局上下文”或概览“共享环境 → 配置”，填写 Markdown 文本，勾选启用及注入方式，保存。可写入：

```markdown
## 可用执行资源
- 本机：macOS arm64，已安装 Python 3、tmux。
- 辅助执行机：Linux x86_64，SSH 别名 x64-debug。
- 远端任务目录：/work/sapper/<任务名>。
- 用途：运行、调试本机无法原生执行的 x86/x86_64 程序。
- 执行前检查程序架构、解释器和依赖，再选择运行环境。
```

以上是示例，需替换为实际环境。这里只传递信息和使用约定，不建立 SSH 连接、安装工具或改变授权范围。认证继续使用原有 SSH 配置。配置文本不会作为 shell 脚本执行。

| 方式 | 生效时间与范围 |
| --- | --- |
| 启动提示词 | 主会话、指挥官、将军、侦察兵、验证者等通过统一启动入口，在新建、后台派发和恢复时追加；保留原角色说明与系统提示 |
| 会话 hooks | SessionStart／UserPromptSubmit 读取最新配置；同版已由启动提示词提供时不重复输出文本；新版可在后续消息时注入 |

默认两种方式均可选择，未填写配置时保持停用。若仅启用提示词，运行中会话需新建或恢复才能加载修改；若启用 hooks，下一次实际 hook 事件可读取更新，不代表保存时向所有正在执行的模型请求实时推送。

每个角色显示当前配置、启动注入版本、最近 hook 检查版本和时间。显示“已提供”表示启动参数或 hook 已提供该版上下文，不证明模型已经理解或执行。修改后尚未接收新版的角色显示“待更新”；已结束的角色保留当时记录，恢复时读取最新版。

停用会停止后续注入，但不会删除已进入会话历史的旧内容。新版本带版本标记，说明它替代此前的共享环境描述。

## 3. 存储、并发与边界

配置保存于 `--state/global-context.json`，默认 `.sapper-web/global-context.json`，文件权限 600；hook 回执在 `--state/context-receipts/`。正文最多 12,000 字符。保存使用版本校验，其他页面已经更新时拒绝覆盖并保留当前输入，可点击“重新读取”获取最新版。

不写入用户全局 `~/.claude`，不把共享环境存成题目事实，也不把模型密钥配置复制给 hooks。管理审计只记录版本和启用状态，不记录正文。上下文正文会按配置提供给原模型，启动参数及原终端记录可能包含它。

自动覆盖范围是本 Web 服务管理、继承其环境的 Claude Code 角色及其派发。高级原 `auto/dispatch` 也会在原调用处追加上下文；hooks 模式会合并项目 hooks，保留其他设置。旧 commander／worker／watchdog 在明确存在 `SAPPER_GLOBAL_CONTEXT_FILE` 时启用相应启动适配；不设置该变量时保持旧命令行为。

升级前已经运行、未继承此环境变量的旧会话，需要通过受管入口恢复或重新启动后接入。独立启动的外部会话、其他容器或用户、任意非 Claude 引擎，不会被静默修改为已接入状态；手动登记本身不等于注入完成。旧比赛平台／其他供应商未因此重新完成端到端验收。

## 4. 实现与接口

| 位置 | 作用 |
| --- | --- |
| `lib/sapper_context.py` | 读取／渲染共享文本、版本去重、hook 回执、原 CLI 的可选启动适配 |
| `lib/sapper_web.py` | 配置保存、并发校验、全局概览聚合、受管环境路径传递 |
| `lib/sapper_workspace.py` | 原生角色追加提示词、派发与恢复、各角色版本状态 |
| `lib/sapper-hook.py` | 两个事件注入共享文本；仍保持原图按 cwd opt-in，不继承其他题目的图 |
| `lib/sapper.py` | 原模型调用中仅对显式受管环境追加上下文，保留原角色说明、参数、stdin 与工具循环 |
| `web/overview.js`、`overview.css` | 概览页、全局配置表单、进入／退出工作区 |

```text
GET  /api/overview
GET  /api/context
POST /api/context
```

接口沿用登录、Host／Origin 校验及写入 CSRF。概览只返回配置版本和状态；正文通过配置接口读取。没有新增可执行任意 shell hook 的管理入口。

## 5. 验证记录

79 项自动测试通过，覆盖原 71 项及新增配置持久化／权限、版本冲突、登录与 CSRF、概览统计、真实 hook 子进程、原模型调用协议保留、字面文本不执行、后台派发、运行中更新、恢复、仅 hook 注入及重试时凭据轮换。原模型的自动测试使用假 CLI，不连接实际靶场。

浏览器检查了：已有任务时登录仍进入概览；保存全局配置；从概览进入题目；指挥官后台派发侦察兵；v1 → v2 的待更新提示及后续 hook 回执；返回概览；刷新仍停留概览。浏览器未记录到错误。

本机真实 Claude Code 验证：资源别名 `qa_x64_shared_7421` 和架构 `Linux x86_64` 仅写入共享配置，任务要求从已注入说明识别它们。验证角色生成两行结果文件，内容与配置一致，并通过原 sapper CLI 写入带角色 creator 的事实；进程正常退出，hook 回执与启动版本均为 1。该检查没有连接声明的测试服务器，不把配置注入通过当作 SSH 可达性或远端工具可用性的证明。

Linux／HTTPS、Docker 构建、真实比赛平台与任意供应商的既有环境验收边界保持。
