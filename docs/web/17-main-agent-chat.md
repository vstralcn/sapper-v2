# 工作区终端、文件与 Agent 状态

2026-11-07

## 用户流程

工作区默认打开“终端与文件”：左侧浏览题目文件，中间操作原生终端，右侧查看全部 Agent 的任务与状态。
主 agent 与执行者使用相同的终端入口；补充信息、回答问题和纠偏时，选中对应角色并点击“接管输入”。

创建或绑定工作区后填写任务说明，使用“派发角色”启动主 agent。
首次启动自动完成项目接入，以原生 TUI 形式运行，并选中主 agent 的终端。
已有主 agent 时，派发请求送入该会话，由模型核对依据并安排执行者。

主 agent 离线时，派发窗口可选择“恢复旧会话，沿用原模型”或“按当前配置新建”。窗口同时显示原会话模型和当前角色默认模型；修改工作区默认模型只影响新建会话。角色详情也显示恢复时实际采用的配置。
恢复失败的提示包含原会话配置、当前默认配置和具体原因，并保留在派发窗口中。新建会话使用新的 UUID，保留旧会话、工作文件和共享图。

角色列表展示全部已登记角色，不再截取前四个活动角色。点击交互角色打开终端，点击限时执行者打开活动日志，点击离线角色进入详情，可按原生 UUID 恢复。
角色与协作拓扑继续提供指挥关系、筛选、状态依据和生命周期操作。事实与意图、运行记录、文件与附件保留各自入口。

## 状态依据

终端页、角色详情、协作拓扑与总体概览使用同一套状态映射：

- 在线性由 tmux pane 和运行退出记录确定。
- 原生交互会话按登记 UUID 增量读取 JSONL，展示最近观测到的模型处理、工具执行、等待用户或本轮结束。
- 限时执行者从 stream-json 的工具调用、工具返回、问题及结果事件记录执行阶段。
- 缺少在线性或当前运行阶段的证据时，显示“状态未确认”；进程存活本身不作为正在执行的证据。
- 已结束的运行显示“已离线”，详情保留退出原因。恢复后的新运行不会沿用旧阶段。

状态读取只观察原生记录，不触发调度、模型调用或会话恢复。每次扫描有字节上限；尚未读完整段记录时显示未确认，下次刷新继续。
切换工作区会清空旧终端及角色视图，并拒绝过期请求覆盖当前工作区。

## 会话与生命周期

主 agent 继续使用原生 Claude Code，保留工具、hooks、MCP、Skills、模型配置和原生 UUID。
新派发及界面恢复默认使用 TUI；已有网页协议会话可在角色详情点击“使用交互终端”，停止旧运行后恢复同一 UUID，子角色继续运行。
历史会话记录保留，旧双向协议 API 继续兼容显式 `execution_mode=chat` 的调用；工作区不再加载独立网页对话界面或轮询对话历史。

每个工作区保存自己的主 agent 身份，角色状态 API 一并返回该身份。
启动／恢复主 agent 同步启动该工作区的 watchdog；启动 watchdog 失败会回滚主进程。
停止主 agent 同步停止 watchdog；工作区停止只处理所属角色及服务。
watchdog 依据当前主 agent 身份进行续轮、恢复和退出判断，跳过已停止的历史指挥官及其暂停、等待和恢复失败记录。

主 agent 负责澄清目标、调度、接收汇报和传达纠偏；执行者完成任务内的技术工作。
是否侦察、如何拆分、何时升级或换路线由模型结合证据和资源判断。

## 验证入口

- `tests/check_main_chat_browser.py`：隔离 Web API 与真实 tmux/PTY，使用原生 CLI 替身检查默认终端、派发、输入、文件、全部角色状态、终端切换、原 UUID 恢复、子任务继续运行、工作区隔离和窄屏布局。
- `tests/check_legacy_chat_browser.py`：离线历史角色、刷新、工作区切换和协作拓扑；核对原始历史未改写，浏览不启动模型。
- `tests/check_navigation_browser.py`：并行加载、即时切换、过期响应拒绝和旧视图清理。
- `tests/test_sapper_workspaces.py`：原生角色阶段读取、部分 JSONL 处理、终端传输、精确恢复和生命周期。
- `tests/test_sapper_run.py`、`tests/test_agent_topology.cjs`：结构化执行阶段及统一状态映射。
- `tests/test_sapper_chat.py`：显式双向协议兼容，以及切回 TUI 时身份、watchdog 和子任务的连续性。
