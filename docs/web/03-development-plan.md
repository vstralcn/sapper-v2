# 开发计划与验收

版本：v0.3 · 2026-11-01 · 基础 Web 功能已实现；下列里程碑保留后续完整规划，实际完成情况见第 6 节。

本文保留基础版的阶段与验收记录。后续工作区规划见[原生角色协作规划](./06-workspace-and-roles-plan.md)，当前完成范围以[实现与验收记录](./07-workspace-implementation.md)为准。

## 1. 范围

只为原 agent 增加网页操作和观察能力，复用原 CLI、tmux、worker、watchdog、工具环境、会话和 JSON 事实图。通用模式以可选分支摆脱平台必填配置，保留比赛模式。解题引擎和事实图数据库重构不属于本轮。

## 2. 开发顺序

| 阶段 | 工作包 | 验收证据 |
| --- | --- | --- |
| M0：现状与接入契约 | 列出现有启动、会话、worker、图、消息、知识库、配置和恢复操作；记录原参数和默认值 | 网页动作可映射到具体原命令，能力保留清单明确 |
| M1：可观察、可操作的会话 | 后台绑定既有运行、原生终端、worker 列表、图和文件；采集原日志 | 接入不重启原 agent，浏览器退出后任务继续，终端保留原交互 |
| M2：日常网页管理 | 创建／启动、附件、消息／hint、worker 操作、多模型配置、成果下载 | 日常操作无需打开本地 tmux；模型配置能在原引擎和恢复中生效 |
| M3：通用模式 | 显式通用入口、平台可选、任务说明／附件、无平台看板 | 非比赛任务无需 `BENCHMARK_*`；原比赛路径和工具能力保持 |
| M4：服务器与交付 | 登录、HTTPS 网关、WS／日志、留存、备份与端到端回归 | 本机与目标 Linux 验证后提供真实启动命令与部署说明 |

M1 可提前使用，但不代表完整网页管理已完成；完整首版包含 M1–M4。

### M0：需要先核实的行为

- 原启动和会话身份、工作根目录、同题共享图和恢复路径。
- 原 CLI／tmux 输出来源、可采集程度及现有日志订阅。
- 原模型环境、特定网关分支、Key 池、watchdog 轮换如何影响每个 pane。
- 原停止、平台关闭、自动保活和指挥官派发的关系。

上述检查限定在 UI 接入所需范围，不做无关的 agent 算法或解题效果优化。

### M1–M2：优先交付的操作链路

接入原会话 → 看原终端与日志 → 查看 worker／事实图／文件 → 发消息并上传附件 → 保存多组模型配置 → 用选定配置从网页启动同一 agent → 停止／恢复并下载成果。

保留原生终端作为完整功能入口；结构化按钮逐项接入原命令，不以少数按钮覆盖不了原能力为由简化 agent。

### M3–M4：通用模式与服务器

通用模式是明确选择，不覆盖原比赛配置。适配层只跳过不适用的平台操作并传入任务说明，复用原角色、工具、通信、记忆与恢复。

部署包分别说明 Web 层和原执行环境的持久目录、端口、凭据与启动依赖。经实际目标服务器验证前不承诺容量或多协议兼容性。

## 4. 网页验收

| ID | 场景 | 成功条件 |
| --- | --- | --- |
| W01 | 接入既有运行 | 不重新初始化图、不派发重复任务，状态来源可核实 |
| W02 | 终端交互 | 原 TUI 可显示、输入、中断和调整尺寸，断开网页不结束任务 |

| W08 | 服务器 | HTTPS 下终端、文件、日志和控制可用；未登录无法访问 |
| W09 | 结果管理 | 原始成果、脚本、图和日志可下载，普通导出不含凭据 |

## 5. 验证方法与完成标准

- 修改原接入点时运行相关既有测试；用命令生成／参数对照验证原行为未被默认改变。
- 使用可复现的轻量任务验证会话、工具、通信、图和恢复，不先依赖长时间比赛。
- 两个协议家族分别通过原 agent 的真实工具调用验证，普通 API 连通不能代替。
- 通过浏览器测试完整操作链路，再在目标 Linux 网关下验证 WS、上传和日志续传。
- 尽量使用文本、接口和 DOM 检查；仅必要时截图，不生成设计渲染图。
- 完整首版须同时满足能力保持与网页验收；未支持的原功能至少可通过完整原生终端操作，不能被移除。

前版的 18–29 工作日估算基于另一种重构方案，不再适用。先完成 M0 接入核对，再按实际终端、配置与平台接入点估算；当前不提供未经核实的新工期。

## 6. 当前实际完成情况

已完成基础控制台及工作区扩展：已有目录绑定、项目级接入、原 Claude Code 启动／精确恢复、角色与派发树、本地协作、PTY 实时终端。79 项既有及新增测试通过，已完成本机浏览器操作和真实模型的小任务检查。Linux／HTTPS 与镜像构建尚待目标环境验证。实际命令见[启动与使用](./05-running.md)。

M1–M2 已具备基础网页操作、PTY 流式终端、原生会话恢复与角色管理。v0.7 优先完成非平台原生功能：31 个命令原参数表单、模板与编队配置编辑、知识库原生新增／导入／正文、peer 授权通信、图生命周期、原自主／指挥官／轮转／编队流程。详见[最新覆盖与验收](./09-native-capability-coverage.md)。知识库编辑／删除、日志搜索与留存、整站配置导入导出和备份不是原 CLI 已有功能，本轮未增加。M3 已通过显式本地工作区分支实现无平台协作，默认比赛分支保留；旧模式的供应商轮换与其他引擎尚未统一接入新工作区管理。M4 已提供认证、网关参数与可选镜像文件，目标 Linux／HTTPS 和镜像构建仍待实际环境验收。原 agent 核心保持。

当前默认首页为总体概览；全局环境文本可通过启动提示词与 hooks 统一提供给受管角色，详见[全局上下文与总体概览](./08-global-context-and-overview.md)。

v0.8 已实现模型协议选择、模型列表发现／筛选、保存前连接测试和后台 HTTP 适配服务管理；Responses／Chat Completions 已用真实 Claude CLI 连接本地测试服务验证工具往返。原解题循环继续保留，任意远端网关兼容性待各自验证，见[模型配置验收](./10-model-protocols.md)。

[Web 原生角色提示词对齐](./11-native-role-prompts-plan.md)已完成核心修复：统一渲染来源，恢复原指挥官／将军／士兵的职责和有条件协作说明，补齐真实看板、创建预览及版本记录；没有引入强制派兵或新提交策略。完整回归 109 项通过；真实长时多角色比赛表现仍需在实际任务中观察。

下一项高优先级修复是[会话恢复后不自动继续](./12-resume-continuation-plan.md)：当前 `--resume` 已正确恢复身份和基础职责，但交互式会话没有新用户消息，会停在输入框；旧后台 shell 也不会恢复。计划增加“恢复并继续／仅恢复终端”两种明确语义、幂等续作消息、后台任务中断提示及对应回归，不重放旧命令或扩大提交授权。
