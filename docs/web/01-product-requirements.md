# 产品需求与交互

版本：v0.3 · 2026-11-01 · 以保留原 agent 能力为前提，以下为完整目标；当前基础版本的完成范围与限制见[启动与使用](./05-running.md)。

## 1. 使用边界

网页是现有 agent 的操作与观察入口，agent 仍负责计划、分工、执行、使用工具、保存事实与会话。CTF、安全分析、代码和研究以任务说明、附件和可选模板区分，不新建另一套解题内核。

保留原 CLI 与直接 tmux 使用方式；网页退出不使 agent 退出，网页服务重启不重启 agent。新增配置或行为必须显式选择，原有启动参数、权限、模型版本和工具不因接入网页而被默认改写。

## 2. 页面与功能

| 页面 | 首版内容 | 现有能力的接入方式 |
| --- | --- | --- |
| 总览 | 运行列表、指挥官／worker、最近活动、异常 | 读取原进程、tmux、看板及文件 |
| 新建／接入任务 | 创建任务、填写目标、附件、工作目录；接入已有运行 | 调用原初始化／启动入口或绑定已有会话，不重建原图 |
| 任务工作区 | 终端、日志、状态、消息输入、文件、图视图 | 原会话镜像及受控命令适配 |
| Agent 管理 | 查看角色与模型、派发／停止 worker、发送消息 | 复用 `worker.sh`、原 commander 与通信入口 |
| 模型配置 | 多组配置增删改查、测试、按启动对象选择、切换提示 | 按原引擎映射启动参数与环境，不另写 API agent 循环 |
| 文件与记忆 | 附件上传、任务文件预览／下载、事实／意图／hint、报告导出 | 使用原工作目录和 `.sapper/`，写图走原接口 |
| 模板与知识库 | 查看／管理任务说明、可选模板、知识条目 | 不静默替换原提示词或工具规则，保留原配置 |
| 系统设置 | 登录、环境诊断、日志留存、配置导入导出 | 仅管理 Web 层和明确选定的运行配置 |

## 3. 典型流程

1. 在网页选择已有工具环境及模型配置，创建任务或接入已有会话。
2. 查看实际要执行的命令、工作目录、引擎、模型与配置作用范围，启动原 agent。
3. 在工作区观察真实终端、日志、图和文件；从网页补充信息、上传附件或操作终端。
4. 指挥官继续自主分工，网页呈现其行为；用户也可调用原有 worker 管理入口。
5. 通过原停止／恢复方式控制运行，下载原始成果与日志。

## 4. 运行中补充信息

- 对指定 agent 发消息使用原 `worker.sh msg` 或已授权的 `sapper send`；不向任意发现的其他会话发送。
- 需要持久保存的说明使用原 hint／事实图接口，附件先写入选定任务目录，再告知 agent 文件路径。
- 页面分别显示“附件已保存”“消息已送入终端”“有回应”。仅送入输入框不能宣称 agent 已读或已采用。
- 原引擎没有消费回执时直接显示未知；不为实现回执替换其上下文循环。
- 原 TUI 忙碌时按其输入／中断机制处理，保留输入队列和手动终端入口，避免重复回车和重复提交。

## 5. 运行控制语义

| 操作 | 要求 |
| --- | --- |
| 接入已有会话 | 先只读，不重启、不重配、不重新派发任务 |
| 手动输入／中断 | 明确目标终端，使用原 TUI 操作语义，提示对当前步骤的影响 |
| 停止 worker | 对应原停止动作；区分是否同时关闭平台实例，不能默认附加 `--close` |
| 恢复会话 | 沿用原引擎会话与恢复入口；无法恢复时如实展示，不声称有新增检查点能力 |
| 暂停 | 原运行方式没有可靠暂停时不提供虚假的“已暂停”；明确区分中断当前步骤与暂停整次运行 |
| 切换模型 | 展示是当前会话支持的切换，还是需要重启／新会话；不承诺热切换 |
| 重新运行 | 显式新建或复用目录，保留原资料和过程，不覆盖已有结果 |

watchdog 与 commander 可能按原规则恢复或补充 worker。网页停止操作须说明实际作用对象，不能仅杀一个进程便报告整个任务永久停止。

## 6. 多 LLM 配置

配置内容包括名称、目标引擎、协议标签、API 地址、模型 ID、密钥和可选原生参数。用户可存储多组并为指挥官／worker 选择。

- Anthropic 兼容与 OpenAI 兼容是需求；可用范围取决于现有引擎和网关是否支持，必须验证工具调用、长会话和原有功能。
- 普通聊天请求成功不足以认定可用于原 agent；不支持的配置显示具体原因，不用简化聊天代理顶替。
- 使用原引擎已支持的环境、配置、参数或经验证的外部协议网关；不自动升级原 CLI。
- 配置保存与应用分离，展示影响哪些会话。原模型／Key 轮换继续保留，其与多个配置并存的行为需要验证。
- 密钥写入后不完整回显，配置导出默认不含密钥；网页日志和管理操作记录脱敏。
- 若原引擎无法暴露某项用量或能力，显示未知；不新增未经验证的费用硬封顶承诺。

## 7. 观察与日志

默认保留原生终端作为完整操作入口，再叠加便于阅读的看板、图视图和日志过滤。

- 展示指挥官、worker、工具执行及 watchdog 的真实输出；来源和采集时间可区分。
- 终端历史快照与持续日志分开：前者可能有限，后者从启用采集时开始，缺失段明确标注。
- 日志支持自动跟随、暂停滚动、搜索、分页、下载和断线重连；暂停滚动不影响原任务。
- 原 `-p` 路径存在缓冲时如实标记，不为了 token 级显示更换引擎输出模式。
- 图由原 `.sapper/` 加锁读取，不将页面缓存当作最新事实或 agent 的真实运行状态。

## 8. 首版验收

1. 原终端模式仍可使用；已有工具、权限选择、协作、知识库、hooks、图与会话机制保留。
2. 接入已有 agent 后无需重启即可观察和使用；Web 服务重启不改变原运行。
3. 相同配置下，网页与原入口生成等效的命令、环境、目录和会话组织，不改变 agent 的默认决策逻辑。
4. 网页完成创建／接入、启动、终端交互、发消息、传附件、读图、查看／下载日志与成果。
5. 多组模型配置可保存并按对象应用；实际供应商支持通过原 agent 工具调用验证，轮换和恢复不串配置。
6. 保留比赛模式；显式通用模式可运行非比赛任务，不自动请求平台或提交结果。
7. 经 HTTPS 网关访问，登录、终端、上传、日志、图和控制均可用，未登录无法访问。
8. 暂停、停止、已读、用量与恢复等状态有真实依据，不用管理页面的乐观状态代替原运行事实。

当前已覆盖基础控制台、题目工作区、原生会话、角色协作与 PTY，79 项回归及本机浏览器链路通过，真实 Claude 小任务完成。Linux／HTTPS、镜像及任意供应商仍待环境验收；不能将本机通过记录当作全部目标均已验收。详见[实现记录](./07-workspace-implementation.md)。
