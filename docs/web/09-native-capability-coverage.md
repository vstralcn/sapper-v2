# 非平台原生功能：网页覆盖与验收

版本：v0.7 · 2026-11-02。

## 本轮范围

优先补齐 sapper 原本已有功能的网页入口，继续使用原命令、模型调用、工具、提示词模板和 `.sapper` JSON 图。侧栏和工作区工具栏新增“原生功能”，无需手写终端命令即可填写原参数、预览实际命令和目录、选择模型配置并执行。输出与退出码进入原运行记录，可下载日志；命令需要交互时仍可操作原 tmux 终端。

表单字段直接读取 `sapper.build_parser()`，不是维护另一份删减命令参数表。当前覆盖 32 个非平台命令及其参数，包含 family 组合管理与止损；明确排除 `arena`、`bench` 和 `flag --submit`，也不提供在 Web 内递归启动 `web`。原 CLI 的这些入口保留。平台目标启动、交卷和比赛策略不在本轮范围。

## 命令覆盖

| 原命令 | 网页入口与行为 |
| --- | --- |
| `init` | 原生功能：初始化原图，强制覆盖须确认 |
| `status`、`graph` | 原生功能：输出原状态或完整图数据 |
| `validate`、`frontier`、`pick` | 原生功能：校验、就绪意图、下一意图；记忆页另有校验／就绪快捷操作 |
| `fact`、`intent`、`hint` | 原生表单及记忆页：事实、意图、人工补充，支持原参数；事实可附证据来源、复现命令与项目内工件，意图可归入已登记的解法族 |
| `show`、`doc`、`recall` | 节点、文档读取／写入／原终端编辑、原检索；记忆页可直接检索并打开节点 |
| `claim`、`release`、`done` | 原生表单及意图卡片：领取、释放、带结果事实完成；保留领取者和确认门槛；`done` 同样可附证据来源／复现命令／工件 |
| `complete`、`confirm` | 完成项目、确认意图；继续调用原 Store 校验 |
| `brainstorm-pick` | 选择原批次方案，确认所选并结束同批其他方案 |
| `dispatch` | `reason`／意图探索／`verify`／`brainstorm`／`blindspot`；模板、模型、超时、原权限参数及 dry-run |
| `auto` | 原生自主推理／探索循环、验证、轮数／探索数、分钟／截止时间预算 |
| `command` | 原多任务指挥官循环，选择任务根目录、时间片、编队配置等；保持原派发逻辑 |
| `sweep` | 原多任务轮转，选择根目录、总预算和每题时间等 |
| `fleet` | `init/up/down/status/hire/fire/workers` 原 tmux 编队操作；配置编辑见下文 |
| `peers` | 发现、列出、明确授权／撤销通信对象；发现不会自动授权 |
| `send`、`capture` | 向原授权对象发送消息、读取终端，保留原通信日志选项 |
| `setup`、`teardown` | 原项目接入／撤销；默认保留图，`purge` 删除图须确认 |
| `view` | 原静态 HTML 导出、HTML 输出、原图服务；记忆页／工具栏可直接查看图 |
| `flag` | 原本地 Flag 台账、题目标识、说明；不提供比赛提交 |
| `kb` | 原 `add/search/show/list/import/root`；可选“全局知识库”，无需先创建工作区 |
| `family` | 原 `add/list/show/metric/spend/budget/decide` 解法族组合与止损；族状态、并发、尝试与手工记账 USD 预算在 Store 内生效，不取代人工复核 |

原生 CLI 已有的多种角色通过原工作区角色界面继续管理；`auto/dispatch/command/sweep` 的实际执行另外登记为“原 CLI 流程”。原编队的其他 pane 可从终端列表观察并登记已有角色，不根据进程名称猜测身份。

## 使用

1. 按[启动说明](./05-running.md)启动，登录后选择工作区或侧栏“原生功能”。
2. 选择原命令并填写参数，指定模型配置或继承原环境。`command/sweep` 默认显示 Web 的任务根目录，可改为已在网页绑定的其他目录。
3. 点击“预览原命令”，检查命令、cwd、模型配置和编队内容，再执行。修改参数、配置或模型后重新预览。模型密钥不会出现在预览中。
4. 工作区命令进入运行记录；全局知识库命令直接显示输出。日志可下载，交互式命令可进入对应 tmux 终端。
5. 常用图操作可在“事实与意图”页直接完成；知识库侧栏可新增、导入、检索并查看完整正文与下载原 JSON。

路径是执行机路径。原生功能可访问任务根目录和在网页绑定的工作区目录；绑定结果持久保存，角色和 watchdog 进程也能读取，无需启动时预先增加允许范围。原知识库仍可使用其配置根目录；其他外部资料先在网页绑定其目录即可。旧 `--workspace-root` 配置保持兼容。Web 私有目录仍受保护，原 agent 工具按原执行环境工作，这不构成 shell 沙箱。

### 编队与模板

“原生编队配置／提示词模板”可读取、修改工作区相对路径下的编队 JSON 和 `templates/*.md`。编队沿用原 `session/root/deadline/panes` 结构；未存在的配置先显示样例，保存才落盘。保存有内容版本校验，拒绝覆盖另一处刚修改的文件。

模板未覆盖时显示仓库原版，首次保存会补齐缺失的原版模板，保留已有自定义内容，避免只保存一个模板导致其他原调度步骤找不到模板。不改仓库默认模板，不通过配置编辑器直接修改 `.sapper` 内部数据。

`fleet up/hire` 和指挥官派发继续创建原生 tmux 会话／window；受管环境同步所选模型配置、共享上下文和 tmux socket。编队是独立会话，停止指挥官的运行记录不会级联杀掉已有编队；使用原 `fleet down/fire` 控制它们。需要独立隔离时用 `--tmux-socket NAME` 启动 Web。

### 原 CLI 流程与 Claude 会话

交互式角色保留真实 Claude UUID，可按原 UUID 恢复。原 `auto/command/sweep` 是多次调用模型的 CLI 循环，不代表一个可恢复的交互式 Claude 会话，因此显示“原 CLI 流程”和“原流程参数”，不生成假 UUID，也不让工作区 watchdog 用 UUID 恢复它。重新运行时通过原参数表单启动。

向原 CLI 循环的“补充说明”写入原 hint，后续步骤按原机制读取；不声称非交互进程能实时接收聊天。原预算、原工具、原权限选项和确认机制保持，Web 不增加每条工具命令的审批。

Web 受管 `view` 继续导出／服务 HTML，但不会在服务器上自动弹出桌面浏览器。原 CLI 独立运行时的打开行为保持。`teardown` 成功后仅清理 Web 生成的导入块与桥接文件，保留用户说明和默认保留的图。

### 证据来源与解法族

`fact` 与 `done` 的表单直接来自原解析器，因此自动出现“证据来源”“复现命令（每行一条）”“工件路径（每行一个）”三项。复现命令只作为文本记录，Web 不执行；工件须在执行机项目目录内，复制为 `.sapper/artifacts/<sha256>`，单文件上限 64 MiB。`sapper validate` 核对工件的存在、大小与 SHA-256，网页校验／就绪快捷操作同样走原 `validate`，因此能发现被篡改或缺失的工件。

“事实与意图”页的快捷表单走的是另一条图操作接口，现同样接受这三项：服务端用与 CLI 相同的 `normalize_fact_evidence` 校验，工件由同一 `sapper_evidence.ingest_artifacts` 在题目目录内入库（拒绝符号链接、目录外路径和缺失文件），`done` 也接受证据。记录详情显示来源、复现命令与工件摘要，列表以“证据”标记；旧记录没有证据字段时保持原样。

工作区角色的基础提示词（`sapper-native-roles/6`）也写入了这三个参数与凭据禁忌；新建角色和显式恢复的角色自动获得，运行中的旧角色不被热改。

`family` 表单提供 `add/list/show/metric/spend/budget/decide`。族状态、同族最多两个开放意图、尝试预算、手工记账 USD 预算与无改善止损都在原 Store 内判断：族进入 parked／solved／ruled_out／need_human 后，同族新意图和原生派发会被拒绝，网页没有绕过这些门槛的参数。恢复或调整预算需要显式理由；成本只按实际账单手工登记，不做 token 估算，也不为解法族另建第二套 API。

## 兼容修正

为使原命令在题目目录和网页选定环境中可靠运行，修复了原实现的几处问题：`kb import --path` 被忽略；`sweep` 把 `.sapper` 当成题目目录并重复拼接 `auto`；含空格路径的引擎前缀和编队命令转义；指挥官 hire 丢弃 `--model`；worker 名称按空格错误拆分；编队 shell 未进入配置所在目录。

原 tmux 增加可选 `SAPPER_TMUX_SOCKET`，默认 socket 不变。仅 `SAPPER_WEB_STATE` 明确存在时同步受管环境及抑制服务器桌面自动打开。没有改写原模型工具循环，也没有删除比赛代码。

## 验收证据与边界

- 94 项自动回归全部通过，覆盖原有测试、工作区／hooks／上下文测试，以及本轮原生功能测试；命令目录测试逐项对照原解析器的 32 个命令和字段。Python 编译、四个前端 JS 语法检查、原 commander 脚本语法检查及 `git diff --check` 通过。
- 证据来源与解法族的增补回归 14 项通过（工件哈希／越界拒绝、原子 `done`、族并发上限、尝试与 USD 预算、止损与显式恢复、提示词摘要限量、Web 图操作证据写入与拒绝越界工件、HTTP 认证接口同一路径）。合并远端新版后的全量 216 项回归本机 215 项通过，保留 1 项既有 tmux 折行环境失败（`ORIGINAL_FLEET` 被窄 pane 折行；干净远端同样失败，与本次改动无关）。
- `tests/smoke_evidence.py` 可重复冒烟：CLI／Console／真实 HTTP 三条入口各 17 项检查，连续多轮稳定通过（不含模型调用，不产生平台提交）。
- 隔离真实 tmux 中执行图操作、文档、Flag 台账、HTML 导出、peer 授权和发送／捕获、知识库新增／导入／检索、接入撤销及重新初始化。
- `dispatch` 各步骤提示词 dry-run；`auto/sweep/command` 与编队启动／雇用／解雇／停止使用可控假模型执行，验证原循环、模型配置传播和含空格路径。假模型测试不作为供应商兼容证明。
- 本机真实 Claude Code：网页后端启动原 `auto --minutes 1 --max-steps 1 --timeout 45`，对隔离目录内 `proof.txt` 的 `6 * 7 = 42` 证据完成目标，原项目状态为 `completed`、退出码 0。
- 浏览器实际完成原生事实表单预览／执行、图校验与检索、意图领取／带证据完成、全局知识库新增与完整正文查看、编队 JSON 保存、调度 dry-run、原 `auto` 参数启动与完整日志查看；该轮浏览器无 warning/error 日志。

本轮是非平台原生功能的网页覆盖。Linux／HTTPS／Docker 构建、任意模型网关兼容和长时间并发任务仍未实测；这些环境验收不以本机测试代替。知识库编辑／删除、整站备份等原 CLI 没有的能力，也不在此次“补齐原生功能”的完成声明内。

## 接口

新增 `GET /api/native/catalog`、`POST /api/native/{workspace}/preview`、`POST /api/native/{workspace}/execute`、`GET/POST /api/native/{workspace}/config`。全局 KB 的 workspace 为 `global`。沿用原认证与 CSRF 校验，预览摘要校验参数／模型／编队配置一致性，需确认的操作要求确认字段，重复 request ID 不重复启动。

另提供工作区 `recall/validate/frontier`、原 Store 的领取／释放／完成／批次选择图操作，以及 `GET /api/knowledge/{id}` 正文与下载。执行记录继续复用 `/api/runs` 和原日志／终端接口。
