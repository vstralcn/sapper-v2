# 技术架构与接入设计

版本：v0.3 · 2026-11-01 · 设计原则：原 agent 继续运行，Web 负责操作、读取和展示。本文保留完整设计，基础版实现与差异见[启动与使用](./05-running.md)。

## 1. 当前代码依据

以下为原代码接入依据。当前已经使用假模型 CLI 和独立 tmux 完成基础测试，没有运行真实模型或完整比赛容器任务。

| 能力 | 当前实现 | Web 接入方式 |
| --- | --- | --- |
| 事实意图图与写入校验 | [lib/sapper.py](../../lib/sapper.py) 的 `Store`、`locked`、图与 hint 命令 | 继续读写原 `.sapper/`，写操作调用原接口 |
| 模型执行与自主循环 | 同文件的 `run_claude`、`cmd_auto`、`cmd_command`、`cmd_fleet` | 调用原命令，不替换 CLI 或工具循环 |
| 图查看页 | 同文件的 `cmd_view`、`_view_serve` 和 [view_template.html](../../lib/view_template.html) | 复用图数据和展示；当前只有 GET 页面与图接口 |
| worker 管理 | [worker.sh](../../docker/commander/worker.sh) 的 `spawn/msg/peek/list/board/hint/kill` | 包装现有操作，保留参数与行为 |
| 会话保活与凭据轮换 | [watchdog.sh](../../docker/commander/watchdog.sh)、[工作区监控](../../lib/sapper_workspace.py)、[指挥官监控](../../lib/sapper_commander.py) | 按运行模式分支；工作区监控循环委托指挥官监控处理续轮与恢复 |
| 平台依赖 | [entrypoint.sh](../../docker/commander/entrypoint.sh) 强制检查比赛变量；worker 启动会请求平台 | 为显式通用模式增加可选分支，保留原比赛入口 |
| 已有多引擎／网关路径 | worker 中 `--engine`、`--gw`、`--model` 及 pane 配置 | 在原支持范围映射网页配置，具体协议能力另行验证 |
| 知识库、hooks 与通信 | [lib/kb.py](../../lib/kb.py)、[sapper-hook.py](../../lib/sapper-hook.py)、sapper peers/send/capture | 保留原文件、授权与调用方式 |

`SAPPER_BIN` 在不同文件有不同用途：Python 调度中表示模型 CLI 前缀，worker 脚本中表示 sapper 命令；网页配置必须区分，不能将其当作统一的任意模型适配接口。

watchdog 的入口按模式分流：原比赛／CLI 模式执行 `watchdog.sh` 的 shell 循环，负责原有 pane 保活、凭据轮换和比赛时限；`SAPPER_MODE=workspace` 时脚本转入 `sapper_workspace.py watch()`。工作区循环监控所属角色并委托 `CommanderMonitor` 处理主 agent 状态、续轮和恢复；具体状态与确认依据见[指挥官续轮](./14-commander-liveness.md)。

## 2. 结构

```text
浏览器
  │ HTTP 管理与输入／SSE 原生终端输出
登录与 HTTPS 网关
  │
Web 后台：配置、会话绑定、操作适配、日志采集、文件管理
  ├─ 原 sapper CLI
  ├─ 原 worker.sh 与 tmux 会话
  ├─ 原 watchdog、CLI 会话和配置
  └─ 原工作目录、.sapper/、知识库、日志与成果
```

不新增解题调度器、原生模型 API agent 循环或另一套事实图权威存储。后台技术栈可采用 Python，与现有代码便于集成；前端只负责管理交互，框架不影响原运行。

Web 可以先接入已有运行，再提供启动功能。关闭或重启 Web 不销毁 tmux、修改图状态或重发任务。

## 3. 数据所有权

- 原 `.sapper/` JSON、会话目录、pane 配置及工作文件继续由原 agent 管理，Web 不迁移、不双写、不修改 schema。
- Web 独立保存模型配置、登录信息、会话绑定、管理操作记录和日志游标，可用受限文件或小型数据库；不能用它覆盖原状态。
- 读图按原锁获取一致快照，写入通过原 `Store`／CLI，不直接从网页改 JSON。
- worker 的共享图符号链接和独立会话目录保持原规则，文件预览允许合法共享图但限制跨出受管根目录。
- Web 显示的“运行状态”组合进程、tmux、原图和日志证据；失联或过期时显示未知，不推断已完成。

## 4. 操作映射与必要接入点

| 网页动作 | 适配目标 | 需要处理的细节 |
| --- | --- | --- |
| 接入运行 | 枚举选定的 tmux 会话、工作根目录和 pane | 不默认接管全部本机会话 |
| 启动 | 原安装／初始化／commander 或自主循环入口 | 采用原权限与工具；传递显式选择的配置 |
| 创建／停止 worker | 原 `worker.sh spawn/kill` | `kill --close` 涉及平台关闭和提交，须与普通停止分开 |
| 发送说明 | 原 `worker.sh msg` 或已授权的 `sapper send` | 目标校验、文本传递、重复发送防护 |
| 持久补充 | 原 hint／fact／doc 接口 | 标注用户来源；不宣称原 agent 已采用 |
| 查看终端 | PTY 附着到指定 tmux 会话／pane | 断线只释放 Web 连接，不结束原会话 |
| 查看图／知识 | 原图构建、校验、kb 命令 | 保持原记忆结构和检索能力 |
| 恢复 | 原 CLI 的会话恢复、watchdog 现有入口 | 依引擎判断；不保证未知 CLI 的无损续接 |
| 配置模型 | 原参数、环境、配置文件与 Key 池 | 新建会话应用／原生切换／重启的区别必须可见 |

包装命令使用参数数组，用户消息作为字面内容传递，避免网页输入被当作宿主机 shell 代码。原 agent 自己执行命令的能力不因此被删减。

## 5. 多模型配置

每组配置保存名称、原引擎、协议标签、地址、模型、密钥引用、原生参数和配置版本。作用对象为指挥官、某次启动的 worker 或原有 Key 池，页面显示实际生效位置。

- 不通过改写 Web 服务的全局环境来同时配置不同 worker；在各自启动上下文应用。
- 原实现目前按特定网关家族处理模型和凭据，并由 watchdog 执行轮换。需要增加配置绑定接入点时，只扩展配置选择与持久化，默认行为和原轮换策略保持。
- 轮换、重启与恢复必须读取同一配置绑定；网页修改默认配置不能悄悄影响其他活跃会话。
- 优先沿用原引擎的兼容协议；若必须接入其不支持的协议，使用经验证的配置／外部网关适配，不以自写简化 agent 替代。
- OpenAI 兼容与 Anthropic 兼容都需通过真实配置验证原工具调用；现有特定引擎分支不等于任意供应商兼容。
- 密钥在管理层受限或加密保存、界面不完整回显、导出与日志脱敏。原 CLI 运行所需凭据按原机制提供，不能宣称原执行环境已经实现新增强隔离。
- 不因网页接入升级原 CLI 或替换镜像工具版本；协议不兼容时报告具体缺口。

## 6. 终端与日志

先提供完整原生终端，再提供结构化看板。终端是保留原 CLI 交互能力的必要入口，不能只显示模型最终文本。

- 通过受控 PTY 连接原 tmux，保留 TUI、按键、尺寸调整与人工输入；断开浏览器不发送结束会话指令。
- `capture-pane` 用于接入时的可见历史，原日志文件用于历史查询；新增输出采集应避免覆盖已有 `pipe-pane` 订阅。
- 当前 pane 历史有限，终端重绘也不是完整审计轨迹。日志只对已采集部分作完整性声明，不能补造接入前输出。
- 保存带序号的日志块和游标，浏览器按序去重并补播；采集缺口、轮转、截断和来源可见。
- 当前实现将原 tmux PTY 输出经 SSE 传送，输入和尺寸调整用 HTTP，保留现有认证与 CSRF，无需额外 WebSocket 服务。网关须关闭流式响应缓冲并配置心跳及超时。
- 原 Python `-p` 调度使用一次性 `capture_output`，部分输出需等结束。先保留并说明该特性，不能擅自改变原输出协议以追求逐 token 展示。
- Web 记录发出的管理操作与发送结果，不据此生成模型内部推理或伪造已读状态。

## 7. 停止、恢复与 watchdog

现有 watchdog 会恢复部分死亡会话，指挥官也可能再次派发 worker。简单 Web 按钮与这些机制可能冲突，需要在实现前分别验证：

1. 关闭 Web／终端连接是否保持原任务运行。
2. 原 `worker.sh kill`、中断当前 TUI 与停止整个运行分别会留下哪些进程和恢复行为。
3. 用户停止整次运行时，如何先使该运行停止派发／保活，再清理其进程，且不影响其他运行。
4. 恢复是否仍使用原目录与会话；原进程存活时不重复创建。

仅在 Web 显式停止操作中协调这些组件，不改变无人干预时原 watchdog 的保活策略。没有可靠暂停语义时，页面不提供“整次运行已暂停”的承诺。

## 8. 非比赛任务接入

既要去除使用时对 TSecBench 的强制依赖，也要保留原比赛能力：

- 增加显式通用模式；原模式和默认启动行为继续保留。
- 通用模式从用户输入、附件和靶标／目录说明构造任务，不调用比赛题目启动、交卷和关闭接口。
- 原 commander、worker、工具、图、通信和会话结构不变；以可选任务说明或模板替换仅适用于比赛的任务文本。
- 原平台命令、flag 记账和已授权的提交流程继续可用，不在 Web 包装时删除或额外改成逐步审批。
- 无平台场景的看板使用本地任务与原图信息，平台计分列显示不适用。

这部分需要少量显式接入改动，仅增加模式选择和平台可选分支，不重写解题策略或限制原工具。

## 9. 服务器接入与文件

个人模式提供管理员登录，保护页面、文件、日志和终端。服务器经 HTTPS 网关访问，支持根路径或明确配置的路径前缀。首次部署仍需安装依赖、接入域名和保存凭据。

后台只绑定明确受管的运行、目录和终端；普通上传内容不能选择任意宿主机路径。保留任务使用原工具和已授权目录的能力，上传、下载和 Web 认证限制不能变成新增的 agent 工具白名单。

Web 元数据、原任务目录、会话与日志分别持久保存。备份在稳定状态获取，包含文件与版本说明；普通导出不含模型密钥。Web 重启／升级不自动升级原引擎或重启原会话。

## 10. 启动状态

当前入口为 `python3 lib/sapper.py web` 或 `python3 lib/sapper_web.py`。实现使用标准库 HTTP 服务、静态 HTML／CSS／JS 和本地 xterm.js。PTY 由 tmux 持有，SSE 传输出，HTTP 传输入／尺寸；已有外部订阅不兼容时回退快照。工作区／角色元数据保存于 Web 私有目录，原图仍由 Store 管理。现有 `view` 保持原样，Web 通过受认证接口展示原图。详情见[启动与使用](./05-running.md)及[实现记录](./07-workspace-implementation.md)。
